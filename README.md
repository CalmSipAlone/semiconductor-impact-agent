# 半导体产业链影响分析智能体

本项目面向金融投研竞赛，计划构建由大语言模型组织分析、由查询与计算工具提供依据的系统，研究政策变化、原材料价格波动等事件沿半导体产业链传导的路径，以及对相关企业经营和盈利的影响。

更新日期：2026-10-08。项目计划描述目标，当前进度描述已经实现并验证的功能。B 的工作进度、内容汇报和成员协作需求集中在第二部分。

## 一、项目整体计划

### 1. 研究问题与首版范围

原计划以半导体出口管制等政策事件为切入点，研究“上游设备材料 → 中游设计、制造、封测 → 下游应用”的影响传导。后续讨论补充了原材料价格因素，尤其是光刻胶及其上游原料的价格变化。

项目需要回答：

1. 事件直接影响哪些材料、产品、工艺或企业，有哪些证据？
2. 影响沿哪些产业关系向下游传导，哪些关系已经核验，哪些仅是假设？
3. 在明确的参数与适用条件下，可以计算哪些成本或盈利指标？
4. 如何保存可检查的来源、计算过程和运行记录？

首版建议聚焦一个事件、一条材料或工艺链、3～5 家资料较充分的企业和一个主要量化指标。材料价格案例是否作为主线、具体光刻胶类别、原料追溯深度、企业名单及分析期间，仍需团队确认。这些建议不表示实施范围已经确定。

### 2. 目标流程与输出

> 输入事件与范围 → 检索资料 → 查询产业关系 → 获取价格、指标和参数 → 确定性计算 → 大模型组织解释 → 结构化报告 → 保存运行记录

报告计划包含事件概述、对象范围、传导路径、企业影响、计算结果、引用证据、参数与假设、缺失信息及适用边界，并区分事实、推论和观点。参数不足时说明不能计算的内容，不生成无依据的数值。

原材料价格、配方比例、生产成本、产品售价和企业盈利需要分别定义口径。某项原料涨价不能直接等同于下游利润或售价同比变化。传导与计算依据由 A/C/E 提供，B 实现，D 调用和解释。

| 错误与预算 | 超时、最多调用次数、重试；partial、error、缺数据、模型不可达时的处理 | 接入错误状态与运行日志 |

D 使用工具返回的数值、对象和证据编号。计算工具完成后引用其结果，不自行增加不存在的计算结果，也不将演示、情景或待核验资料描述为已确认事实。

**最低可用交付：** 一个实际可运行的模型样例，完成“调用查询工具 → 读取来源 → 输出带证据编号结果”。

#### 6.6 各成员的共同交付规则

- 从[模板](templates/README.md)复制填写，使用 UTF-8、保留表头；模板外的说明附在资料备注中，新增字段先与 B 对齐。
- A/C/E 使用同一套企业、材料与产品编号。参数至少指定企业或产品之一，材料编号对应一个具体等级。
- 原始 PDF 与整理 CSV 一起交。B 登记文档编号后，CSV 用 source_document_id 与 source_page 成对引用；页序号从 PDF 第一页起计数。
- 提供来源和公开日期；价格观测日期、财务期间、公开日期分别填写。未知公开日期注明，不用导入当天替代。
- 数值说明单位、币种、期间与口径。value_type 区分事实、估算与情景；估算/情景必须有 assumption_note。
- 核验过的标记 verified，未核验的标记 pending，并注明审核成员。缺失项说明原因与补充来源。
- 交付附简短清单：文件、负责人、对象、日期范围、核验状态和缺失项；修改时说明版本和改动。

#### 6.7 下一轮建议交付顺序

| 顺序 | 负责人 | 优先交付 | B 可推进 |
| --- | --- | --- | --- |
| 1 | 全体，A/C/E 牵头 | 同一主案例、对象、期间与指标 | 固定任务和范围 |
| 2，可并行 | C/E | 对象、企业、关系、规格与价格 | 真实入库及关系、价格验收 |
| 2，可并行 | A | 公式、指标、参数、手算和缺失处理 | 开发并验证计算 |

| 3 | 全体 | 同一案例完整资料，审核首份结果 | 贯通查询、计算、解释、报告与记录 |

近期最需要的是同一案例的一组可核验资料、一套可手算的规则和一个可运行模型入口。资料到齐后，B 可以将当前的数据与查询模块推进成完整分析流程。

## 三、运行与使用

### 本机演示

已验证环境：Python 3.12.14、pypdf 6.10.0。PowerShell 中执行：

~~~powershell
cd 'D:\Desktop\semiconductor-impact-agent'
$projectPython = 'C:\Users\Lenovo\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $projectPython examples/run_query_demo.py --output outputs/query-demo.json
& $projectPython cli.py --db data/processed/phase2-demo.sqlite stats
~~~

预期入库为 7 份文件、11 条证据、3 个对象、1 家企业、2 条关系、2 条价格、1 个参数和 1 个财务指标；重复导入不会增加记录。业务查询默认排除演示数据和待核验记录，数值默认只取事实类型，演示脚本会显式放宽。

其他电脑可创建独立环境并安装固定依赖：

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe examples/run_query_demo.py --output outputs/query-demo.json
~~~

本机直接输入 python 会使用另一套解释器，建议使用上面的已验证环境。检查命令为：

~~~powershell
& $projectPython -m unittest discover -s tests -v
& $projectPython scripts/audit_workspace.py --output outputs/audit/workspace-audit.json
~~~
