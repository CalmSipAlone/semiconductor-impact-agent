# 系统技术方案

## 方案定位

本文整理原计划书的架构，并补充此前讨论中的实施建议。所有补充建议均待团队确认。当前没有实现代码、模型接入或运行验证。

## 原计划书的四层架构

1. 数据层：采集、清洗与存储公告、财报、行业资料、新闻等；保存结构化数据和文档证据。
2. 工具层：文档解析、财务计算、产业关系查询和信息检索。
3. 智能体层：大模型进行任务规划、工具选择、状态管理、错误处理和分析组织。
4. 应用层：接收任务、展示结果、下载报告，并提供外部接口。

原文提出了向量数据库、关系数据库、LangChain/AutoGen、NetworkX/Neo4j及MCP等选择，尚未确定最终组合。比赛截图要求至少使用一个大语言模型、提供结构化结果、记录执行过程并提交完整源码；具体技术实现要求应以完整规则核对，不能仅由技术名词推定。

## 首版实现建议

先使用本地资料导入，减少对在线采集的依赖；先跑通一条完整分析流程，再增加复杂前端、更多资料来源和多智能体协作。模型运行位置、接口访问权限及现场网络条件仍需确认。

### 数据流程

1. 导入本地PDF、CSV和队友核验的资料表。
2. 登记文件编号、来源、发布日期、导入时间及内容哈希。
3. 按页提取文本；关键表格和数值允许人工核验后导入。
4. 统一企业、材料名称及数据口径。
5. 保存关系、价格、财务指标、计算参数与证据。
6. 向智能体提供稳定的查询和计算接口。
7. 生成结构化分析结果与运行日志。

### 数据类别

| 类别 | 必要信息 |
| --- | --- |
| 企业 | 编号、名称、证券代码（如有）、产业环节 |
| 产品和材料 | 编号、名称、具体类别、规格、用途 |
| 关系 | 上下游对象、关系类型、有效期间、证据、核验状态 |
| 价格 | 对象、规格、日期、数值、单位、币种、报价口径、来源 |
| 财务指标 | 企业、报告期、指标、数值、单位、证据 |
| 计算参数 | 指标含义、适用对象、数值、单位、期间、依据、参数性质 |
| 文档证据 | 文件编号、来源、日期、页码、原文片段 |

“用于生产”“企业生产”“企业采购”“已证实供货”分别建模。价格不能只按“树脂”等宽泛名称匹配。参数性质区分已核验事实、估算及情景假设。

### 首批工具接口建议

| 工具 | 输入 | 返回 |
| --- | --- | --- |
| search_evidence | 分析对象、问题或关键词 | 证据片段、文件编号、页码 |
| query_relations | 对象编号、关系类型、查询深度 | 关系、关联对象和证据 |
| query_prices | 材料、规格、期间 | 价格记录、单位、币种和来源 |
| calculate_cost_impact | 经核验或明确标注的计算参数 | 数值、公式、假设和缺失项 |

接口名称仅为建议。B与D需要确认实际输入输出、错误结构及调用方式。缺少参数时返回缺失项，不自动编造数值。

### 示例计算（纯情景演示）

假设某树脂占某产品基期生产成本的30%，树脂采购价上涨10%，采购量和其他成本不变，则该产品生产成本变化率约为：

`30% × 10% = 3%`

上述比例没有真实企业依据，仅用于解释计算。成本占比不等于配方质量占比；产品成本变化不等于产品售价、企业利润或芯片售价同比变化。后续财务传导公式与参数由A确认，材料适用性由C、E确认。

## 输出与追溯

结构化结果至少包括事件、传导路径、受影响企业、计算结果、参数与假设、引用证据、缺失项及适用边界。区分事实、推论和观点。

每次运行登记运行编号、数据版本、文件访问、工具输入输出、计算过程、模型与Prompt版本、模型响应及最终结果。只记录可观察的操作和结果，不以获取模型内部思维过程作为实现要求。

确定性数值计算应在相同参数下保持一致；模型文字输出的复现需要说明重跑条件和缓存回放方式，不能保证任意模型调用逐字一致。
