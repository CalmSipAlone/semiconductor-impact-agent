# 计算机科学与技术成员工作规划

## 职责与工作量

成员B负责数据工程、后端开发及系统集成。D负责模型和智能体；A、C、E分别核验计算规则、产业关系和材料知识。

此前估计：在具有一定Python和数据库基础、队友同步交付的前提下，一条材料链、3～5家企业、20～40份资料和一个案例的可追溯原型，需要约100～160小时有效工作。此数字是工作量估算，非团队承诺。收缩为少量本地资料的最小演示，约35～55小时，但依赖队友完成相应工作。

## 开发顺序

| 步骤 | B需要完成 | 交付和验收 |
| --- | --- | --- |
| 1. 确认案例 | 与团队固定主事件、材料、企业、输入输出 | 一页需求说明；所有成员对案例理解一致 |
| 2. 定资料及接口 | 给C/E提供关系和证据模板；与A定参数；与D定工具接口 | 资料可直接导入；接口与错误格式明确 |
| 3. 搭建工程 | 建立项目结构与运行说明 | 队友能按说明启动 |
| 4. 导入文件 | 登记文档编号、来源、时间和哈希 | 重复导入不会产生重复记录 |
| 5. 解析资料 | 提取PDF文本并保留页码；关键字段人工核验 | 每个关键字段能够定位证据 |
| 6. 数据存储 | 保存对象、关系、价格、财务和参数 | 可按对象、规格、期间查询 |
| 7. 开发工具 | 实现证据、关系、价格查询和成本计算 | 与手算案例一致；能识别缺失参数和单位问题 |
| 8. 与D联调 | 串联查询、计算和报告生成 | 一个任务能够完整返回结构化结果 |
| 9. 日志与展示 | 保存运行记录；提供简单任务与结果入口 | 报告数字可追溯到参数、计算和证据 |
| 10. 检查与交付 | 检查异常案例；整理依赖与样例 | 队友在另一环境能运行主案例 |

## 建议工程结构

```text
data/raw/          本地原始资料，不默认上传
data/processed/    本地清洗结果
src/ingest/        导入与文档解析
src/storage/       存储和查询
src/tools/         查询与计算工具
src/app/           任务入口与结果展示
src/tracing/       运行日志
outputs/           生成报告
tests/             关键计算及流程验证
```

这是后续开发建议，仓库当前尚未创建这些实现模块。

## 队友依赖

- A：指标口径、公式、参数依据及一个手算样例。
- C：工艺用途、企业与产品关系、传导路径和证据。
- E：具体材料类别、原料关系、规格差异、替代限制和证据。
- D：模型接入、编排、工具调用、结构化输出与错误处理。

C整理核验图谱内容，B实现导入、存储和查询，是建议的职责拆分，需团队确认。A审核报告逻辑，D生成报告，B负责展示与导出接口，同样需确认交接。

## 进度建议

第一天定案例、资料模板和接口；随后完成文件导入、文档解析及存储；再完成工具和联调；最后补日志、展示及运行说明。保留联调缓冲，不把所有时间用于爬虫或界面。

计划书的时间表列10月18日为报名及作品提交截止，但阶段说明写11月提交初赛材料；应核验正式通知并统一后，再确定实际开发日程。

## 验收案例

检查正常流程、参数缺失、单位不一致、关系证据缺失、工具失败，以及相同参数的重复数值计算。每个关键数字必须有计算依据；假设不得冒充企业披露数据。
